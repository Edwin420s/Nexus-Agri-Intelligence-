# Nexus Demo Script (1–4 minutes)

## Before recording
- Run `npm run check`.
- If live integrations are not verified, show the demo in fixture mode and say so plainly.
- If claiming sponsor usage, run a real investigation and retain redacted proof of the successful operation and actual model identity.
- Never show API keys, tokens, or private workspace details.

## Suggested narration

**0:00–0:20 — Problem**
“An agricultural entrepreneur considering tomato farming needs more than a confident chatbot answer. They need to understand market prices, production costs, water and seasonal risks, logistics, and what is still unknown.”

**0:20–0:45 — Ask Nexus**
Submit: “Assess whether small-scale tomato farming in Kirinyaga County is worth investigating, considering market prices, production costs, water and seasonal risks, transport, and buyer access.”

**0:45–1:25 — Show the dossier**
Explain the evidence status and why it was assigned. Open evidence records and show source details, dates, geography, and quality flags. If using fixtures, explicitly state they are synthetic and not real Kenyan market observations.

**1:25–2:05 — Explain uncertainty**
Show missing information, conflicts, and next actions. Emphasize that Nexus distinguishes evidence sufficiency from actual business viability and does not guarantee profitability.

**2:05–2:45 — Sponsor integrations**
Show only integrations that actually ran. For Zetaris, show the real query and a returned record used in the dossier. For Meterless, show the required real operation. For Nemotron, show verified model route/identity and output. Do not describe unverified stubs or fallback as sponsor integrations.

**2:45–3:15 — Close**
“Nexus turns fragmented information into an inspectable investigation. Its value is not that it always says yes or no; it shows the evidence, the gaps, and what needs to be verified next.”

## Demo fallback
If a live provider fails, use clearly labelled synthetic fixtures only where event rules permit, disclose the failure, and do not claim live integration. Capture the failure honestly and explain the product's safe behavior.
